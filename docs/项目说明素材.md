# 上报用项目说明素材

## 项目名称

星图优选电商价格监控系统。

## 项目背景

项目以虚构演示企业「嘉兴星图优选」为业务场景：嘉兴电商运营团队需要持续观察京东、天猫、拼多多上的数码家电价格，识别降价、判断是否达到目标采购价，并比较同款商品在不同平台的价格。以完整可运行的独立演示项目呈现这一需求，没有编造真实客户或商业交付经历。

## 功能范围

系统提供管理员登录、运营仪表盘、监控商品维护、手动及定时采集、7/30/90天历史曲线、商品组跨平台比价、成功/失败采集日志、目标价与24小时跌幅预警、已读处理和全局设置。初始12件商品覆盖三平台，各4件；2个同款组，每件30个历史点加今日点，价格能够逐点复算和对账。

## 技术栈

前端采用 React、Vite、TypeScript、Ant Design、ECharts、React Router；后端采用 Node.js、Fastify、TypeScript 和 REST API；Prisma ORM 默认使用 SQLite，并从统一模型生成 PostgreSQL provider 配置。认证采用 JWT 与 bcrypt，任务由 node-cron 在后端进程内调度，pnpm 管理 client/server 单仓库。提供生产静态托管、Docker/Compose配置和完整启动文档。

## 负责部分

在本独立项目中完成需求整理、数据模型、采集器接口与双轨实现、确定性演示回填、API与参数校验、价格统计、调度与预警引擎、全部前端页面与图表、接口自测和实际浏览器验收、部署配置及交付文档。验证过程保存原始流水、复算结果和截图，而不是用示例文字代替业务数据。

## 难点：数据源不确定性与双轨设计

电商价格接口可能受网络、访问限制、动态渲染与返回结构变化影响。本次京东公开接口实际请求就未获得HTTP响应，存在连接重置等失败；若为了演示连续性补入假价格，会让业务判断失真且难以审计。

解决方法是定义统一 Collector 接口，保留 DemoCollector 与 HttpCollector 两条数据路径。演示路径通过商品ID、日期和采集序号形成可重放随机游走，限制单次幅度与整体区间，保存每次输入快照，所有界面标注演示模拟。真实路径按配置获取JSON或静态网页，检查状态、超时、选择器与金额，失败只记录原因，不产生价格或降价判断。

所有当前价和统计来自成功流水，同一数据被仪表盘、商品列表、详情与比价复用；来源按每条流水而非当前商品配置展示。因此即使切换数据源失败，历史模拟价仍明确标注模拟，真实失败也能排查。调度逐商品捕获错误，预警保持去重和冷却，使外部数据不稳定时系统仍可运行且不误导使用者。

## 可引用的验收事实

- 阶段0：30天演示序列同输入复算30/30一致，最大单步2.458665%，另验证270个小金额边界点。
- 阶段2：最终回归56个API请求、120个断言；另6个昨日日界断言通过。连续失败不停止调度，目标与24小时规则触发后重复记录0条。
- 阶段3：真实Edge浏览器9组操作通过、6张截图、JavaScript错误0；手动采集后列表/详情/最新曲线点一致。
- 最终交付数据、生产验收断言和压缩包信息以 [阶段4报告](stage4-report.md) 及 `outputs/stage4-verification.json` 为准，避免将不同日期的运行结果混写。

## 验证限制

项目可以本地运行并具备部署配置，不宣称已发布公网网站。当前网络未取得京东真实价格；PostgreSQL schema与Compose配置已校验，实际PostgreSQL实例和Docker容器在本机未运行。这些边界在README和阶段报告中如实说明。
