# 星图价格监控：真实运营指南

本项目面向虚构演示企业「嘉兴星图优选」。运营版本增加了空库强密码初始化、演示开关、采集配置预览、金额歧义拒绝、采集地址校验、价格时效、同采集口径的24小时基线、操作审计和一致性备份。实际业务价格仍须来自你有权使用且能够返回有效报价的接口或网页。

**当前未成功实测接通京东、天猫或拼多多的线上价格。** 京东公开接口的外部探针没有获得 HTTP 响应，失败原文保存在阶段0证据；采集器验收使用实际网络请求连接隔离的本地 HTTP fixture，并非平台报价。Docker初验的3个P1问题已修复，原生732项、Docker功能300项与正式只读21项全部通过，见 [Docker问题修复报告](Docker问题修复报告.md)；原499/496/3证据仍在 [历史验收报告](Docker部署验收报告.md)。PostgreSQL连接与公网部署仍需目标主机实测。不要把演示验收等同于已接通平台。

## 1. 用空库初始化正式管理员

Windows PowerShell，从克隆目录的父目录逐行执行；已位于项目根目录时跳过 `cd`：

```powershell
cd xingtu-price-monitor-public
pnpm install --frozen-lockfile
node scripts/setup-env.mjs
```

先编辑 `server/.env`，选择一个新的运营数据库文件，并设置：

```dotenv
DATABASE_URL="file:./operations.db"
NODE_ENV=production
DEMO_ENABLED=false
HOST=127.0.0.1
PORT=4010
CORS_ORIGIN=http://localhost:4010
HTTP_ALLOWED_HOSTS=""
TRUST_PROXY=false
```

首次 `setup-env` 会在文件中生成随机 `JWT_SECRET` 和 `BOOTSTRAP_TOKEN`，不会在日志中输出。保留随机值；若使用已有 `.env`，需补充至少32字符的随机初始化凭证与JWT密钥。文件中的两个秘密应各自独立，不提交或公开。

```powershell
pnpm db:push
pnpm typecheck
pnpm build
$env:NODE_ENV = 'production'
$env:DEMO_ENABLED = 'false'
pnpm start
```

这里仅建表，**不要执行 `db:init` 或 `db:seed`**。打开 <http://localhost:4010>，空库会显示初始化管理员表单。填写管理员名、显示名、强密码和 `.env` 中的 `BOOTSTRAP_TOKEN`。密码至少12个字符、最多72个UTF-8字节；使用密码管理器生成独立随机密码。完成后已有管理员会阻止再次初始化，可以删除部署配置中的 `BOOTSTRAP_TOKEN` 并重启。

`GET /api/auth/status` 可确认 `bootstrapRequired` 和 `demoEnabled`。正式数据库应显示 `demoEnabled=false`。改密码会增加账号令牌版本，旧JWT随即失效；登录过于频繁返回429，等待窗口结束再重试。

演示模式仍支持 `admin / admin123`，仅用于本地演示。**上线必须改密**。复用演示库转运营时，应先备份、改密，关闭演示，再配置实际商品；推荐按以上步骤用独立运营库启动。关闭演示不会删除旧流水，旧模拟点仍保留来源供审计，不作为当前配置下的有效报价。

## 2. 接入有授权的价格数据

先确认你能合法使用数据接口、调用频率以及商品SKU、容量、颜色、地区、会员条件、优惠条件是否一致。本工具读取返回的单一报价字段，不替你取得平台授权或计算未返回的券后价。

商品表单选择「真实采集」，填写真实商品链接和SKU。JSON配置示意：

```json
{"mode":"json","priceUrl":"https://authorized-feed.example/products/actual-sku","jsonPath":"$.data.price","timeoutMs":10000}
```

HTML配置示意：

```json
{"mode":"html","priceUrl":"https://authorized-shop.example/products/actual-sku","cssSelector":".sale-price","timeoutMs":10000}
```

以上域名只说明结构，不能直接使用。JSON字段必须是完整数值或金额，例如 `5999.00`，不接受库存说明、优惠文案、价格区间、零价或负价。CSS选择器必须恰好匹配一个元素；只读取服务器返回的静态HTML，不执行JavaScript，不绕过登录、验证码或反爬机制。

元素为 `立减100元，到手价¥5999.00` 时，默认解析会失败，避免错采100。可缩小CSS选择器，或配置明确且安全的售价提取规则：

```json
{"mode":"html","priceUrl":"https://authorized-shop.example/products/actual-sku","cssSelector":".sale-price","priceRegex":"到手价¥(\\d+(?:\\.\\d{1,2})?)","timeoutMs":10000}
```

规则只允许字面量前后缀和一个标准金额捕获组，不接受任意正则、回溯表达式或多个价格匹配。运费、月供、原价、无报价提示等不会被默认为商品售价。

保存前点击「配置试采」。后端接口为 `POST /api/collectors/preview`，输入完整商品表单，返回实际状态、金额、失败原因、脱敏URL、HTTP状态、耗时、结构摘要与正文哈希，且 `persisted=false`。预览不创建商品、不生成采集流水、不触发价格预警；成功的操作请求可留下审计。核对报价与页面/接口原始返回一致，再保存商品并点击「立即采集」生成正式流水。

京东真实源未填写价格接口URL时，默认尝试 `https://p.3.cn/prices/mgets?skuIds=J_<SKU>`，JSON路径为 `$[0].p`。该默认尝试不保证可用；拦截、超时或解析失败必须保留失败状态，不用模拟价替代。天猫、拼多多必须配置可使用的JSON接口或有效HTML选择器。

目前不提供平台OAuth、付费授权申请或自定义认证请求头管理。需鉴权的商户数据源，可由你管理的网关在服务器侧持有凭证并返回单一价格字段；不要把长期令牌写进前端代码、截图或日志。

## 3. 请求地址与采集审计

默认只允许公网HTTP/HTTPS的80/443端口，禁止地址携带用户名密码，禁止本机、内网及特殊用途地址。DNS返回的所有地址都要通过检查，实际连接固定本轮已检查的地址。跳转最多3次且每跳重新验证，禁止HTTPS降级HTTP；超时覆盖DNS、响应头、响应体及解析，最长30秒；解压后的正文最大1 MB。

确需访问经过审核的内网网关时，由部署管理员在后端环境设置精确端点，例如：

```dotenv
HTTP_ALLOWED_HOSTS="price-gateway.internal:8443"
```

不支持通配符；未写端口只允许标准80/443，不会放行一个主机的全部服务。此设置只放在部署环境，不由商品表单控制。修改后重启后端。不要为了绕过平台失败而放行任意地址。

采集日志保留来源、成功金额或失败原因；真实采集快照保存脱敏请求路径、状态、耗时、响应摘要、正文SHA256及价格口径身份，不落原始响应、Cookie或响应令牌。操作审计可以按后台审计接口查看；备份仍包含完整业务数据及密码哈希，应按正式数据保护。

## 4. 比价和预警怎样读

`currentPrice`始终来自最新成功流水；失败不会改变历史价格。页面同时展示成功报价时间和最近采集尝试状态。报价超过 `2 × 全局间隔 + 宽限` 分钟即陈旧，宽限为 `max(5, min(全局间隔, 60))`。默认30分钟间隔对应90分钟有效期。

来源、SKU、价格URL、JSON路径/CSS选择器或售价提取规则改变后，旧报价与新配置不兼容，也视为不可用。旧价格仍保留原金额与来源供对账，但不参与有效最低价标记。停用商品同样不参与有效排名。运营模式不采集演示商品，也不在商品列表和有效比价中混入模拟商品。若全组没有有效报价，界面明确展示数据不足，不凭旧价标最低。

24小时跌幅必须用同商品、同来源、同价格配置身份的成功流水作为基线；在当前成功点前24小时附近寻找最接近点，允许时间误差为全局间隔，最多60分钟。72小时前旧价、模拟价或旧配置价格不会充当真实基线。没有合格点时不触发24小时规则。预警保存基线记录ID、价格、采集时间和来源，便于复查。

目标价预警与24小时跌幅预警保留未处理去重和24小时冷却。修改目标价、阈值、启用状态会使用已有流水重评，不生成新价格。价格过期或配置失配时解除当前提醒；历史触发记录仍可查询。常驻页面会刷新数据，重要运营决策仍应查看采集时间、失败原因及报价条件。

## 5. 在线备份与恢复

在项目根目录执行：

```powershell
pnpm db:backup
```

脚本仅支持SQLite。它用Prisma执行 `VACUUM INTO` 生成在线一致快照，原库不重建、不执行seed，不直接复制正在写入的db/wal文件；行为依据 [SQLite官方说明](https://www.sqlite.org/lang_vacuum.html)。快照保存到 `work/backups/xingtu-时间-随机ID.db`，旁边JSON包含字节数、SHA256、`quick_check`结果及各表行数。每次生成新文件，保留旧快照。文件权限在支持的平台设为仅当前用户读写。

成功日志不输出数据库连接串、密码或密钥。备份中可能含商品接口配置、用户密码哈希和业务历史，不放进源码包、公共网盘或Git仓库。建议定期执行并把成功快照和清单加密复制到另一存储位置；脚本不会自动删除旧备份，按团队保留策略管理磁盘空间。中断产生的文件没有通过清单校验时，不用于恢复。

恢复采用新文件，保留原库用于回退：

1. 停止全部后端进程/容器，核对备份JSON的SHA256与 `Get-FileHash -Algorithm SHA256` 输出一致。
2. 把选定快照复制到新的、不存在的数据库文件，例如 `server/prisma/restored-20261004.db`。不要覆盖或删除原库及其journal/wal文件。
3. 修改 `server/.env` 为 `DATABASE_URL="file:./restored-20261004.db"`，重新生成独立 `JWT_SECRET`，使恢复前的登录令牌全部失效。
4. 运行 `pnpm start`，检查健康接口、管理员登录、商品数、采集流水数、预警及价格统计。**恢复时不执行 `db:init` 或 `db:seed`**。
5. 确认后让调度继续，保留原库和快照至团队确认可以清理。PostgreSQL请用其原生备份工具 `pg_dump`/恢复流程，`db:backup`会拒绝PostgreSQL连接。

## 6. 部署与持续验收

必须部署为一个后端进程/一个实例：node-cron调度与商品互斥都在进程内，不能直接水平扩容或用PM2多实例模式。进程常驻、健康检查、磁盘持久化、HTTPS反向代理和日志留存由部署环境提供。默认不信任转发IP；仅在受控反向代理且无法绕过代理直连后端时使用 `TRUST_PROXY=true`，否则登录限流会被伪造转发头影响。

Docker运营部署先把独立随机密钥、初始化凭证存入私有部署环境，再执行：

```sh
export DEMO_ENABLED=false
export CORS_ORIGIN=https://your-real-domain.example
docker compose -p xingtu-price-monitor up -d --build
```

`JWT_SECRET`至少32字符；`BOOTSTRAP_TOKEN`空库首次初始化至少32字符；`HTTP_ALLOWED_HOSTS`默认留空。Compose默认关闭演示，只建表，不seed；主卷持久化数据库，另一个卷保存 `/app/work/backups`。初始化管理员后创建实际商品，执行预览及第一次成功采集。日常备份：

Compose 设置 45 秒停机等待，服务收到停止信号后取消未开始任务，等待在途请求和落库。采集轮次分别显示成功、失败、中断；意外退出后，启动恢复遗留轮次，保留已有流水，未完成商品可立即重采或等下一轮。旧版本没有任务账本的遗留轮次只能保留当时已知计数，不能反推未知任务归属；轮次说明会写明此限制。

预警页分别展示当前触发规则和历史提醒。规则在 24 小时冷却期间再次触发仍计入当前活动数，冷却只抑制新提醒；已读表示运营人员看过提醒，不代表当前价格恢复。升级验收证据见 [Docker问题修复报告](Docker问题修复报告.md)。

```sh
docker compose -p xingtu-price-monitor exec app pnpm db:backup
docker compose -p xingtu-price-monitor cp app:/app/work/backups ./work/
```

复制出的备份仍是私人业务文件；容器卷与业务卷同宿主机，应另做加密异地副本。恢复前停掉容器并在受控维护过程复制到数据库卷的新文件，再更改`DATABASE_URL`。

运营启用前逐项核对：至少一件实际商品真实采集成功；默认密码已修改；演示关闭；价格与原始接口对账；失败原因可见；成功报价时间和有效最低价正确；跨24小时后出现有效基线；模拟/旧配置不能触发真实跌幅；备份已恢复验证；应用重启后单实例调度继续且不会重复启动。

隔离自测证据见 [采集器验收](../outputs/operations-collector.json) 与 [备份验收](../outputs/operations-backup.json)。备份脚本本轮在独立10000行库上同时完成20笔事务，验证快照余额/流水同一时刻及恢复完整性。自测证明程序行为，实际平台数据可用性必须在你的授权数据源与目标部署网络持续验证。
